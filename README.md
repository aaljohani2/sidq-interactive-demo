# صِدق | SIDQ — Interactive Concept Demo

**SIDQ / MIDA V1 — Cyber-Physical Diagnostic Attestation**

عرض تفاعلي عربي (RTL) يشرح فكرة التحقق الفيزيائي المستقل من بيانات الأنظمة السيبرانية الفيزيائية. يحتوي على نموذج ثلاثي الأبعاد قابل للتدوير، بيانات اصطناعية حية، رسم بياني، ولوحة لتجربة أربعة سيناريوهات.

> **مهم:** هذه محاكاة مفاهيمية وليست منصة تشخيص حقيقية. لا تتصل بمحرك أو وحدات ESP32 ولا تعرض نتائج اختبارات أو نسب دقة مثبتة. التصاميم ثلاثية الأبعاد رمزية وليست مخططات تصنيع أو توصيات توصيل كهربائي.

## العرض المباشر

بعد تفعيل GitHub Pages من الفرع main والمجلد /root:

https://aaljohani2.github.io/sidq-interactive-demo/

**تفعيل النشر:** Repository → Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main → /(root) → Save.

إذا كانت إعدادات Pages غير مفعلة، لن يعمل الرابط حتى يحفظ صاحب المستودع إعدادات النشر ويكتمل نشر GitHub.

## سيناريوهات العرض

| الحالة | قناة A | الشاهد الفيزيائي B | الاستدلال التوضيحي |
|---|---|---|---|
| NORMAL | سرعة طبيعية | قياس متقارب | اتساق مبدئي |
| PHYSICAL FAULT | انخفاض سرعة | انخفاض سرعة مع تغير الطاقة والاهتزاز | تغير فيزيائي محتمل |
| SENSOR SPOOF | قراءة سرعة غير مطابقة | قياس سرعة مستقل مختلف | تعارض يستدعي التحقيق |
| REPLAY ATTACK | بيانات تبدو مستقرة | تظهر استجابة مختلفة عند إجراء التحدي | غير محسوم قبل التحدي؛ اشتباه بعده |

**ملاحظة منهجية:** لا تثبت الحالات إمكانية الفصل التام بين الأعطال والهجمات؛ قد تنتج مؤشرات متشابهة من أعطال أو أخطاء معايرة أو اتصال. تحتوي المحاكاة عمدًا على نتيجة «غير محسوم».

## مكونات التصور

- ESP32-A: قناة Telemetry وقراءة مشفّر دوران المحرك.
- ESP32-B: قناة Trusted Physical Witness مستقلة.
- Optical RPM: شاهد بصري لسرعة الدوران.
- INA219: شاهد كهربائي.
- ADXL345: شاهد اهتزاز.
- 12V Encoder Motor: الأصل الفيزيائي الخاضع للملاحظة.

وصف المكونات يعكس تصور المشروع وليس تأكيد تجميعه أو اعتماد السلامة الكهربائية له.

## التشغيل محليًا

المشروع ثابت (Static): HTML + CSS + JavaScript + Three.js، بدون خادم تطبيق.

شغّل خادم HTTP داخل مجلد المشروع، مثال: python -m http.server 8000، ثم افتح http://localhost:8000

يستورد Three.js من jsDelivr عبر الشبكة. إن تعذر الاتصال أو استخدام WebGL، تظل أدوات السيناريو والرسم البياني متاحة مع مخطط ثنائي الأبعاد بديل.

## بنية الملفات

- index.html: الصفحة العربية.
- styles.css: أنماط العرض المتجاوب.
- app.js: محاكاة البيانات والرسم البياني والنموذج ثلاثي الأبعاد.
- favicon.svg: أيقونة تعريف المشروع.

## ضوابط العرض

- يشار إلى البيانات المعروضة بصفتها اصطناعية.
- لا تستخدم القراءات المعروضة في اتخاذ قرار هندسي أو صحي أو مالي.
- لا تدّع دقة كشف أو تفوقًا تجريبيًا دون توثيق مستقل.
- لا يحتوي المستودع على firmware أو خوارزمية إنتاجية أو مخططات توصيل معتمدة أو نتائج مختبرية.
- اختبر الموقع وشبكة العرض قبل تقديمه للجنة.
